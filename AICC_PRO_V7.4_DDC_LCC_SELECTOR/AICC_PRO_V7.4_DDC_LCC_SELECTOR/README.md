# AICC — AI Cataloging & Classification Center

الإصدار 7 من منصة الفهرسة والتصنيف المهنية بمراجعة بشرية. الواجهة عربية RTL، ويعمل المسار
الأساسي محليًا: رفع الصور، OCR، استخراج بيانات، تحقق ISBN، اقتراح DDC/LCC،
إنشاء MARC 21 وMARCXML، كشف التكرار، مسودة قابلة للمراجعة، اعتماد صريح،
بحث في السجلات المعتمدة، تقارير وسجل تدقيق.

الإصدار المطور يستخرج ويعرض: العنوان والعنوان الفرعي، المؤلف ونوع المسؤولية،
بيان المسؤولية، المترجم والمحرر، ISBN ومرشحيه، ISSN، الناشر ومكان وسنة النشر،
حقوق النشر، الطبعة، اللغة، الصفحات، الإيضاحات، الأبعاد، السلسلة، الجمهور،
أنواع RDA، ملاحظات المراجع والكشاف والملاحظات العامة.

## التشغيل السريع على Windows

1. ثبّت Python 3.11+ وTesseract OCR مع حزمتي `ara` و`eng`.
2. فك الضغط واضغط مرتين على `START_AICC.bat`.
3. افتح `http://127.0.0.1:8000`.
4. بيانات العرض: `admin` / `aicc-demo-change-me`.
5. وثائق API: `http://127.0.0.1:8000/docs`.

لأفضل نتيجة صوّر كل صفحة بصورة مستقيمة وواضحة، خصوصًا صفحة العنوان وصفحة
حقوق النشر والباركود. النظام لا يخمّن بيانات غير ظاهرة.

يستخدم مسار OCR قراءتين متكاملتين محسّنتين لكل صورة، ويحلل حتى ثلاث صور
بالتوازي، ويقيس حدة الصورة والإضاءة والتباين والدقة. يمنع الاعتماد عند
رداءة الصورة أو تعارض الأدلة، ويصحح التباسات أحرف ISBN الشائعة فقط إذا اجتاز
الرقم فحص ISBN الرياضي.

## المحادثة الذكية

المحادثة وكيل مكتبي محدود وليست محادثة عامة. يحدد النية ثم يستخدم أدوات
الفهرس أو التقارير أو التحقق أو RAG. يدعم البحث الموضوعي، الفلاتر حسب اللغة
والسنة، الفرز بالأحدث والأقدم والعنوان، السجل النشط، ISBN، MARC، DDC، LCC،
السجلات الناقصة، التكرارات والتقارير. يذكر الأدوات والمصادر في كل رد.

يرفض الوكيل الأسئلة خارج المكتبات والموقع. وإذا لم يجد دليلًا موثقًا يقول ذلك
ولا يخمّن.

تم تجهيز الشات للاتصال الرسمي بـOpenAI Responses API. ضع القيم التالية في
ملف `.env` ثم أعد تشغيل النظام:

`LLM_BASE_URL` و`LLM_MODEL` و`LLM_API_KEY`.

```env
LLM_BASE_URL=https://api.openai.com/v1
LLM_MODEL=gpt-5.6
LLM_API_KEY=ضع_مفتاحك_هنا
```

تحقق من حالة الربط عبر `/api/ai/status`. لا تضع المفتاح في `app.js` ولا
ترسله إلى المتصفح ولا تشارك ملف `.env`.

عند تفعيل النموذج يبقى الرد مقيدًا بالسجل النشط ونتائج الفهرس المحلية، ولا
يُسمح له باختراع مقتنيات.

## وكيل الفهرسة المهنية

بعد تحليل الصور ينشئ الوكيل تقريرًا موحدًا يتضمن عناصر RDA، واختيار المدخل
الرئيسي الشخصي أو المؤسسي أو المدخل بالعنوان، والتحليل الموضوعي، ورؤوس
الموضوعات، واقتراح DDC وLCC والبدائل، وCutter ورقم الطلب. ثم يبني MARC 21
متضمنًا الحقول 040 و100/110 و245 و246 و250 و264 و300 و336 و337 و338 و490
و830 و650 و700 عند توفر أدلتها.

يعرض الوكيل قائمة أخطاء وتحذيرات وتعليمات إعادة التصوير لكل حقل ناقص، ولا
يسمح باعتماد السجل عندما توجد أخطاء وصفية أو أخطاء جودة حرجة.

## قاعدة المعرفة RAG

من واجهة «قاعدة معرفة الوكيل RAG» يستطيع المسؤول رفع ملفات TXT وMD وHTML وCSV
وJSON وPDF وDOCX. يستخرج النظام النص، يقسمه إلى مقاطع، يفهرسه، ثم يسترجع
المقاطع الأقرب للسؤال مع اسم الوثيقة ورقم المقطع. ارفع سياسات الإعارة، خدمات
المكتبة، خرائط الرفوف، الأسئلة الشائعة وأدلة الفهرسة الخاصة بالمؤسسة لكي
تصبح إجابات الوكيل خاصة بالمكتبة فعلًا.

يحتوي المشروع على دليل عام أولي فقط. لا يتعامل الوكيل معه باعتباره سياسة
مؤسسية، ولا يختلق مدة إعارة أو موقع رف غير موجود في وثائق المؤسسة.

## التصوير الموجّه بالكاميرا

اختر «تصوير الكتاب بالكاميرا»، واسمح للمتصفح باستخدام الكاميرا. يقودك النظام
بالتسلسل عبر الغلاف الأمامي، صفحة العنوان، صفحة حقوق النشر، ISBN والباركود،
الفهرس، المقدمة، الغلاف الخلفي وكعب الكتاب. بعد كل لقطة يمكنك اعتماد الصورة
والانتقال، أو إعادة الالتقاط، أو تخطي الصفحات الاختيارية. تُسمى الصور تلقائيًا
بما يساعد وكيل اكتشاف نوع الصفحة.

يمكن التشغيل يدويًا:

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
uvicorn app.main:app --reload
```

## سير العرض

ارفع الغلاف وصفحة العنوان وحقوق النشر والفهرس والمقدمة. تظهر مسودة موثقة،
درجة الجودة والتحذيرات. راجع النتائج ثم اضغط «اعتماد السجل وحفظه». لا تدخل
المسودة في الفهرس قبل الاعتماد.

قبل إدخال الصور اختر نظام التصنيف المطلوب: «تصنيف ديوي العشري DDC» أو
«تصنيف مكتبة الكونجرس LCC». ينتقل الاختيار إلى وكيل التصنيف ويحدد رقم الطلب
والحقل التصنيفي في MARC وبيانات ملصق كعب الكتاب. يبقى الاختيار محفوظًا عند
تعديل المسودة وإعادة بناء السجل.

بعد اكتمال التحليل يظهر «ملصق كعب الكتاب» تلقائيًا داخل قسم الفهرسة والتصنيف.
يتكون الملصق من رقم التصنيف، ورمز المؤلف Cutter، وسنة النشر، ورقم النسخة.
يمكن اختيار مقاس 30×40 أو 25×38 أو 40×50 مم، ثم طباعة الملصق وحده مباشرة.
تتحدث المعاينة بعد تعديل بيانات التصنيف أو حفظ المسودة، ويمنع النظام الطباعة
عند غياب رقم التصنيف أو رمز المؤلف.

## حدود معلنة

- لا يمكن لأي OCR ضمان 100% لكل صورة ممكنة؛ لذلك يرفض AICC الصورة غير المقروءة
  بدل إظهار معلومة مخمّنة، ويبقي القرار الببليوغرافي النهائي للمفهرس.
- أرقام DDC وLCC اقتراحات أولية إلى أن تربط المؤسسة الجداول المرخصة المعتمدة.
- جودة OCR تعتمد على تثبيت Tesseract واللغة وجودة الصور.
- رمز العرض المحلي ليس بديلًا عن مزود هوية مؤسسي؛ غيّره قبل الإنتاج.
- البحث الحالي هجين معجمي محلي للـMVP؛ موصل PostgreSQL/pgvector موثق كترقية إنتاجية.
- عند ضبط مفتاح OpenAI تُرسل الصور إلى Vision، ويُستخدم بحث الويب الخارجي؛
  عطّل المفتاح إذا أردت تشغيل OCR المحلي فقط.

راجع ملفات `docs/` للتثبيت، المعمارية، الأمن، الاختبارات وسيناريو العرض.

## تحسينات الدقة في 6.1

- أُلغي تخمين المؤلف من الأسطر القصيرة؛ لا يُقبل المؤلف إلا من بيان مسؤولية
  صريح أو من سجل موثق مرتبط بـISBN.
- العنوان غير المسمى يبقى مرشحًا منخفض الثقة، ولا يصبح موثوقًا إلا إذا تكرر
  على صفحتين مستقلتين أو طابق سجل ISBN.
- لا تُختار سنة النشر من عدة سنوات متعارضة على صفحات مختلفة.
- عند وجود ISBN صالح يتحقق النظام من Open Library ثم Google Books، ويستخدم
  البيانات الموثقة مع تسجيل أي اختلاف بينها وبين OCR.
- إذا لم توجد أدلة كافية يترك النظام الحقل فارغًا ويمنع الاعتماد بدل إنتاج
  فهرسة خاطئة.

## تحليل الصور بـGPT Vision في الإصدار 7

زر «إنشاء مسودة التحليل» يرسل صور الكتاب إلى OpenAI Vision عند ضبط المفتاح،
ويطلب سجلًا ببليوغرافيًا منظمًا وفق JSON Schema صارم. كل قيمة يجب أن تحمل
درجة ثقة ودليلًا باسم الصورة؛ القيم بلا دليل أو بثقة أقل من 75 لا تدخل السجل.
يظل OCR طبقة احتياطية، ثم يتحقق النظام من ISBN ويسترجع سجل الطبعة من
Open Library وGoogle Books بالتوازي. إذا بقيت البيانات ناقصة يستخدم وكيل
GPT Web Search صفحة الناشر وفهارس المكتبات والمصادر الموثوقة. المصدر الخارجي
يكمل الناقص ولا يستبدل نصًا عربيًا واضحًا من الصور بنقحرة لاتينية.

أضف إلى `.env`:

```env
VISION_MODEL=gpt-5.6
WEB_RESEARCH_MODEL=gpt-5.6
```

اقتراح DDC/LCC الصادر من Vision لا يعتمد تلقائيًا؛ يظهر كبديل حتى يطابق
مصدرًا ببليوغرافيًا أو جدول تصنيف مؤسسيًا.

## البحث الببليوجرافي الاحترافي في 7.2

- يرفض أرقام ISBN الناقصة حتى لو وافقت مصادفة معادلة ISBN-10.
- يمنع العبارات الوهمية مثل «أدلة OCR إضافية» و«غير واضح» من دخول الحقول.
- إذا تعذر التعرف من الصور، يبحث الوكيل بالـISBN أو العنوان الجزئي والمؤلف
  والناشر والسنة والنصوص المميزة المستخرجة.
- لا يقبل تطابقًا بلا ISBN إلا باتفاق مصدرين على هوية الكتاب، ولا يُكمل أي
  حقل دون رابط مصدر له.
- لا يستورد DDC أو LCC إلا من سجل فهرسة يعرض الرقم صراحة للكتاب المطابق.
